wasm-retro-cc

A WebAssembly build of the Retro68 toolchain. It compiles C source into a real classic Macintosh 68k app, all in your browser. Click Compile below and the bundled hello.c goes through the full pipeline. The .bin that drops out runs on a 1989 Mac (or any classic emulator). Source on GitHub. For a fuller editor with a System 7 desktop attached, see classic-vibe-mac.

What's actually happening here?

A compiler is a program that turns C code into a runnable app. For 1980s Macs, that compiler used to only run on a Mac. There are modern ports you can install on Linux or macOS, but they take a non-trivial setup.

On this page, it runs in a tab. When you hit Compile, your C source flows through four old tools we packed into WebAssembly:

  1. cc1 from GCC compiles your C into Motorola 68000 assembly.
  2. as from GNU binutils assembles that into an ELF object file.
  3. ld (also binutils) links the object with the classic Mac runtime.
  4. Elf2Mac from Retro68 wraps the linked output as a MacBinary II file, the format a 1989 Mac knows how to launch.

The resulting .bin is bit-for-bit the same kind of file you'd have gotten on a floppy disk in 1989. Drop it into Basilisk II, Mini vMac, SheepShaver, or an actual old Mac, and it boots.

Credit where it's due

Almost everything you're seeing is other people's work:

  • Retro68 by Wolfgang Thaller is the cross-compiler toolchain we packed up. Without it, none of this would be possible. Elf2Mac is theirs, and the GCC and binutils builds we ship are configured against their patches and the Apple Universal Headers they distribute.
  • GCC gives us cc1, the C compiler frontend, configured to emit m68k assembly.
  • GNU binutils gives us as and ld.
  • Emscripten is how those four native C/C++ programs became the WebAssembly running in your tab.
  • Apple's Universal Headers (the System 7-era Toolbox API declarations) come along for the ride, so #include <Windows.h> means the same thing here as it did in 1992.

So what's new here?

The glue, and the pipeline that ties it together inside a browser tab. That means:

  • a small JavaScript driver (compile.mjs) that runs the four wasm tools end-to-end, source in, MacBinary out;
  • a packaging script that ships the Retro68 sysroot as one brotli-friendly blob plus a JSON index, so your browser fetches a single 1.1 MB file instead of 220 individual header files;
  • synthetic shims for the umbrella headers (Controls.h, Lists.h, Scrap.h, QDOffscreen.h) that the consolidated in-browser sysroot doesn't ship as separate files;
  • workarounds for the dozens of small bugs that turn up when you make four mid-1990s native tools cooperate inside a JavaScript engine. The whole story is in LEARNINGS.md.
